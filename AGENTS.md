# Repository Guidance

## Purpose

This repository is a professional Azure Administrator Portfolio, developed progressively toward the Microsoft Certified: Azure Administrator Associate (AZ-104).

## Portfolio Rules

1. Projects 01–07 are completed and must be treated as frozen unless explicitly requested to change.
2. Do not rename, move, delete, or redesign completed project folders.
3. Preserve existing screenshot filenames and working Markdown links unless explicitly requested otherwise.
4. The Project 07 folder name must remain exactly `07-Enterprise-Azure-Network-Security-&-Connectivity`.
5. Projects 01–08 are completed portfolio projects. Project 08, Enterprise Azure Monitoring and Operations, has been published to GitHub.
6. Select the next project according to the approved portfolio roadmap and the user's explicit instructions. Do not assume or invent the scope of Project 09.
7. Maintain an enterprise and professional Azure Administrator documentation standard.
8. Use accurate Azure terminology and Microsoft-recommended administrative practices.
9. Do not invent Azure resources, configurations, screenshots, validation results, costs, or implementation evidence.
10. Clearly distinguish planned or future enhancements from resources actually deployed and validated.
11. Do not expose passwords, secrets, tokens, subscription IDs, personal credentials, or other sensitive information.
12. Ask for confirmation before making destructive changes to files, Git history, Azure resources, or configuration.
13. Do not commit or push changes unless explicitly requested.
14. When editing documentation, preserve the existing structure and style unless a redesign is explicitly requested.
15. Use concise, professional, enterprise-oriented language.
16. When suggesting Azure CLI, PowerShell, Bicep, Terraform, or Git commands, briefly explain their purpose and ensure they are appropriate for the stated Azure environment.
17. For future Infrastructure as Code (IaC) work, introduce Bicep before Terraform, in accordance with the portfolio learning roadmap.
18. Keep the portfolio focused on Azure administration, governance, security, networking, monitoring, operations, cost management, and Infrastructure as Code as the roadmap progresses.
19. Do not modify files merely to make them different; make changes only when they have a clear purpose.

## Git Workflow

- Inspect Git status before proposing commits.
- Stage only the intended files.
- Use professional conventional commit messages.
- Ask for confirmation before committing or pushing.
- Verify the working tree after Git operations.
- Review root README changes separately from project documentation changes unless the user explicitly approves a combined change.
